## はじめに

「Google Analyticsを入れているのに、売上との数字が全然合わない」「どの広告経由で買ってくれたかが把握できない」——そういった声を、EC運営者の方からよくお聞きします。

GA4（Google Analytics 4）は無料で使える強力な分析ツールですが、ECプラットフォームごとに計測の精度や仕様に大きな差があります。BASE・STORES・Shopifyの3つは国内EC事業者に広く使われているプラットフォームですが、GA4との連携品質はそれぞれ異なります。

本記事では、実際にそれぞれのプラットフォームでGA4計測を設定・運用した経験をもとに、2026年時点での計測精度を比較・整理します。「どのプラットフォームが自社に合うか」を検討している方や、現在運用中のGA4の精度に疑問を持っている方の参考になれば幸いです。

なお、GA4の仕様やプラットフォームの機能は随時アップデートされるため、本記事の情報は執筆時点（2026年8月）のものです。最新の公式ドキュメントも合わせてご確認ください。

---

## BASE：手軽さの代償としての計測限界

BASEはネットショップ開設のハードルが低く、個人・小規模事業者に人気のプラットフォームです。GA4の設定もアプリ追加で完結するため、初期導入の容易さは他の2プラットフォームを上回ります。

ただし、計測精度の面では制約が多いのが現状です。

**購入完了イベントの取得**については、BASEは独自のサンクスページ遷移を持つため、GA4の `purchase` イベントを標準的な方法で取得できないケースがあります。特に、支払い方法によってはサンクスページへのリダイレクトが安定しないことがあり、コンバージョン計測に抜け漏れが生じやすい状況です。

**流入元の追跡**についても、BASE独自のリダイレクト処理によってリファラー情報が書き換わるケースが報告されています。SNS広告から流入したユーザーが「(direct) / none」として計測されてしまうと、広告効果の判断が難しくなります。

また、BASEはGTM（Googleタグマネージャー）の導入ができないプランが多く、カスタムイベントの柔軟な追加が難しい点も、計測の拡張性という観点では課題となっています。

:::message
BASEのアプリによるGA4連携は手軽ですが、コンバージョン計測の信頼性を高めるには、サーバーサイド計測やBA提供のコンバージョンAPIなどの追加対応が必要になる場合があります。
:::

## STORES：標準機能は整備されているが設定の抜け漏れに注意

STORESはBASEと同様に手軽なネットショップ作成ツールとして知られていますが、GA4との連携機能はやや充実しています。管理画面からGA4の測定IDを入力するだけで基本的な計測が始まります。

購入完了イベント（`purchase`）については、STORESの標準機能で取得できるようになっており、注文金額や商品IDなども一定程度パラメータとして送信されます。ただし、送信されるパラメータの項目数や形式がGA4の推奨仕様と完全に一致しない場合があるため、BigQueryエクスポートで詳細を確認したときに想定と異なるデータ構造になっているケースがあります。

**セッション計測の精度**という観点では、STORESのカート・決済フローが独自ドメインや外部ページを経由する場合、クロスドメイン計測の設定が必要になることがあります。この設定を省略すると、ひとりのユーザーの購入行動が複数セッションに分割されてしまい、流入経路が「(direct)」にリセットされてしまう問題が起きやすくなります。

GTMについては、プランによって対応状況が異なります。GTMが使える環境であれば、カスタムイベントの追加や計測の精緻化がしやすくなりますが、使えない場合は管理画面の標準計測に頼ることになります。

## Shopify：GA4計測の拡張性は最も高いが設定コストも高い

Shopifyは3つの中で最もGA4との連携における自由度が高いプラットフォームです。GTMのヘッダー/フッターへの埋め込みが可能なほか、ShopifyのPixel機能（旧スクリプトタグ）を使ったカスタムイベントの送信にも対応しています。

2024年以降、ShopifyはGA4のeコマースイベントを標準でサポートするようになり、`purchase` をはじめとする主要なeコマースイベントが比較的正確に計測できるようになりました。ただし、設定方法はテーマやアプリ構成によって異なるため、正しく動作しているかどうかのデバッグは欠かせません。

**BigQueryエクスポートを使った流入元の分析例**として、以下のようなSQLで注文に紐づく流入チャネルを確認することができます。

```sql
-- Shopify + GA4 BigQueryエクスポートでの流入元別購入分析
SELECT
  collected_traffic_source.manual_medium AS medium,
  collected_traffic_source.manual_source AS source,
  COUNT(DISTINCT
    (SELECT value.int_value
     FROM UNNEST(event_params)
     WHERE key = 'ga_session_id')
  ) AS sessions,
  COUNT(*) AS purchase_events,
  SUM(
    (SELECT value.double_value
     FROM UNNEST(event_params)
     WHERE key = 'value')
  ) AS total_revenue
FROM
  `your_project.analytics_XXXXXXX.events_*`
WHERE
  _TABLE_SUFFIX BETWEEN '20260701' AND '20260731'
  AND event_name = 'purchase'
GROUP BY
  medium, source
ORDER BY
  total_revenue DESC
```

このクエリのポイントは、`ga_session_id` を `UNNEST(event_params)` 経由で取得している点です。GA4のBigQueryエクスポートテーブルでは、セッションIDはイベントパラメータとして格納されており、直接カラムとしては参照できません。また、流入元の情報は `collected_traffic_source.manual_medium` および `manual_source` を使用します。

一方で、Shopifyの注意点として、複数のアプリやテーマカスタマイズが絡んでいる場合、重複したGA4イベントが送信されるケースがあります。Shopify標準のGA4連携とGTMを両方有効にしてしまうと、同じ `purchase` イベントが2重に送信されてコンバージョン数が水増しされてしまう問題が発生します。設定前に既存のタグ・トリガー構成を整理することが重要です。

## GA4計測の精度を高めるための共通対策

プラットフォームの違いにかかわらず、GA4計測の信頼性を高めるために取り組める施策があります。

**1. サンクスページのURLを計測する**
購入完了後に遷移するサンクスページのURLをGA4で確認し、`purchase` イベントが正しく発火しているかをGA4のデバッグビューやBigQueryで検証します。

**2. UTMパラメータの統一運用**
広告や外部リンクにはUTMパラメータを付けて流入元を明示することで、参照元が「(direct)」になる問題を軽減できます。`utm_source`・`utm_medium`・`utm_campaign` を社内ルールで統一することが重要です。

**3. BigQueryエクスポートで生データを確認する**
GA4の管理画面上の数値はサンプリングがかかる場合があります。BigQueryエクスポートを有効にすることで生データを取得でき、より正確な分析が可能になります。以下はセッション数を正確にカウントする基本クエリです。

```sql
-- セッション数の正確なカウント（ga_session_idベース）
SELECT
  COUNT(DISTINCT
    CONCAT(
      user_pseudo_id,
      '-',
      CAST(
        (SELECT value.int_value FROM UNNEST(event_params) WHERE key = 'ga_session_id')
        AS STRING
      )
    )
  ) AS unique_sessions
FROM
  `your_project.analytics_XXXXXXX.events_*`
WHERE
  _TABLE_SUFFIX BETWEEN '20260701' AND '20260731'
```

`user_pseudo_id` と `ga_session_id` を組み合わせることで、ユーザーをまたいだセッションのダブルカウントを防ぐことができます。

**4. コンバージョンAPIやサーバーサイドタグを検討する**
ブラウザ上のJavaScriptによるGA4タグは、広告ブロッカーやITPの影響を受ける場合があります。サーバーサイドでのイベント送信（サーバーサイドGTMやConversions API）を併用することで、計測精度の向上が期待できます。

## まとめ

BASE・STORES・Shopifyの3プラットフォームを比較すると、GA4計測の拡張性・精度という観点では **Shopify が最も高いポテンシャル** を持っています。ただし、設定の複雑さもShopifyが最も高く、正しく設定されていない場合は重複計測などの問題が起きやすいため、導入後の検証が欠かせません。

BASEやSTORESは手軽に始められる反面、計測の柔軟性に限界があります。売上規模が拡大したり、広告費を本格的に投じる段階になったりすると、計測精度の不足が意思決定の妨げになるケースがあります。

次のアクションとして、以下を検討してみてください。

- 現在使っているプラットフォームのGA4タグが正しく発火しているかをデバッグビューで確認する
- BigQueryエクスポートを有効化して生データを取得できる環境を整える
- UTMパラメータの付与ルールを社内で統一する
- 計測に不安がある場合は、専門家へのスポット相談を活用する

GA4の計測は「入れたら終わり」ではなく、プラットフォームの仕様変更や自社のサービス変化に合わせて継続的にメンテナンスしていくことが大切です。
