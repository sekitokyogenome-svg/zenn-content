「提案書を作るのに毎回時間がかかる」――フリーランスやコンサルタントとしてデータ分析サービスを提供していると、提案書の作成は避けて通れない作業です。

データ分析サービスの提案書は構成がある程度パターン化できるため、テンプレートを用意しておくと作成の負担を減らせます。

## この記事でわかること

- データ分析サービスの提案書テンプレート（Markdown形式）
- Claude Codeでテンプレートをクライアント向けに仕立てる方法と、レビューのさせ方
- テンプレートを案件ごとに改善していく回し方

**前提**: テンプレートの対象は「GA4 → BigQuery → Looker Studio」の構成です。テキストエディタとClaude Codeがあれば試せます。GCP側の費用は案件ごとに変わるため、後述の「お見積り」の注記を参照してください。

## なぜMarkdownで提案書を書くのか

提案書のフォーマットは、PowerPoint、Googleスライド、PDFなどさまざまですが、自分はMarkdownで下書きを作成しています。理由は3つあります。

1. **テキストベースなので、バージョン管理しやすい**（Gitとの相性が良い）
2. **Claude Codeで直接編集・カスタマイズできる**
3. **最終的にPDFやスライドに変換可能**（Marpなどのツールを使用）

最終納品物はPDFやスライドにすることが多いですが、原稿をMarkdownで管理することで、テンプレートの再利用と更新が容易になります。

## 提案書テンプレート

以下が、データ分析サービスの提案書テンプレートです。自分が使っている形をベースにしています。クライアントの業種や課題に応じてカスタマイズして使ってください。

スケジュールや構成は一例です。案件ごとに調整する前提で、`{{}}` や `YYYY-MM-DD` はテンプレートの穴埋め箇所です。

```markdown
# データ分析基盤構築のご提案

提出日: YYYY-MM-DD
提出先: {{クライアント名}} 御中
提出者: {{自社名}}

---

## 1. 背景と課題

{{クライアント名}}様では、現在以下のような課題を抱えていると
ヒアリングにて確認いたしました。

- {{課題1: 例）GA4を導入済みだが、データを経営判断に活用できていない}}
- {{課題2: 例）広告のチャネル別効果が把握できていない}}
- {{課題3: 例）月次レポートの作成に毎回多くの時間がかかっている}}

これらの課題は、データの収集はできているものの、
分析・可視化の仕組みが整備されていないことに起因していると考えられます。

---

## 2. ご提案内容

GA4の生データをBigQueryに蓄積し、
経営判断に活用できるダッシュボードを構築します。

### 構成概要

| レイヤー | 内容 | ツール |
|---------|------|--------|
| データ収集 | GA4イベントデータのエクスポート | GA4 → BigQuery（日次エクスポート） |
| データ加工 | 生データのフラット化・集計ビューの構築 | BigQuery（SQL） |
| データ更新 | 集計テーブルの定期更新 | BigQueryのスケジュールクエリ |
| 可視化 | 経営ダッシュボードの構築 | Looker Studio（データの鮮度を設定） |

※ 異常値の通知（アラート）は、必要な場合に別途設計します（本提案には含みません）。

### 納品物

1. BigQueryデータマート（3層設計: raw → staging → mart）
2. 集計テーブルを定期更新するスケジュールクエリの設定
3. Looker Studioダッシュボード（{{ダッシュボード数}}画面、データの鮮度設定を含む）
4. 運用マニュアル（操作手順・トラブルシューティング）
5. 引き継ぎミーティング（1回、オンライン）

---

## 3. 期待される効果

### 広告効果の可視化
チャネル別・キャンペーン別のROASが可視化されることで、
広告予算の配分をデータに基づいて判断しやすくなります。

### レポート作成の効率化
集計テーブルとダッシュボードを定期的に更新する設定にするため、
手作業でのレポート作成の削減が期待できます。

### 顧客行動の理解（拡張オプション導入時）
ファネル分析・コホート分析は「6. 今後の拡張オプション」に含まれます。
オプション導入時には、ユーザーの離脱ポイントやリピート状況を
把握できるようになります。
```

## 構成表の根拠: 自動更新に使う部品

「自動化」と一括りにせず、実際に動く部品に分けて書くのがポイントです。公式ドキュメントで確認できた範囲は次のとおりです。

| 役割 | 部品 | 確認できたこと |
|------|------|----------------|
| 集計テーブルの更新 | BigQueryのスケジュールクエリ | クエリを定期実行し、結果を宛先テーブルに書き込める。既定は日次で、最短5分間隔まで指定できる |
| ダッシュボードへの反映 | Looker Studioのデータの鮮度 | BigQueryは1〜50分ごと、または1〜12時間ごとから選べる。既定は12時間 |
| 失敗時の通知 | スケジュールクエリの通知 | 失敗した実行についてメール通知を設定できる（コンソールで設定） |

出典: [BigQueryのスケジュールクエリ](https://docs.cloud.google.com/bigquery/docs/scheduling-queries)、[Looker Studioのデータの鮮度](https://docs.cloud.google.com/looker/docs/studio/manage-data-freshness)

この表の「失敗時の通知」は、あくまでクエリの実行失敗が対象です。売上の急落といったデータ内容の異常を知らせる仕組みは別物なので、テンプレートでは「別途設計」に分けています。

## GCP利用料をどう書くか

GA4 → BigQueryのエクスポートには、提案書に書いておきたい条件があります（[公式ヘルプ](https://support.google.com/analytics/answer/9358801)）。

- 標準のプロパティでは、日次エクスポートの上限は **1日あたり100万イベント**
- ストリーミングエクスポートを使うと、BigQuery側で **$0.05/GB** の課金が追加される（1GBはおおよそ60万イベントだが、イベントの大きさで変わる）
- 無料のBigQueryサンドボックスにもエクスポートできるが、上限を超えると課金される

このため、月額の目安を先に書くのではなく、「データ量により異なる。見積もり時に実測する」と書き、実際のイベント数を見てから伝えるのが安全です。

## Claude Codeでのカスタマイズ方法

このテンプレートをClaude Codeでカスタマイズする方法を紹介します。

### 基本的な使い方

テンプレートファイルを用意し、Claude Codeに以下のように指示します。以下は入力例で、実際の案件ではありません。

```text
提案書テンプレート（proposal_template.md）を使って、
以下のクライアント向けにカスタマイズしてください。

- クライアント: （入力例）美容系ECサイト
- 課題: 広告費のROASがわからない、カート離脱率が高い
- 予算感: 中程度
- ダッシュボード: 3画面（売上概要、チャネル別、ファネル）
```

Claude Codeはテンプレートの `{{}}` 部分を埋めるだけでなく、クライアントの業種や課題に合わせて文章のニュアンスも調整してくれることが多いです。ただし、出力は必ず自分で読み、金額やスケジュールが案件に合っているか確認します。

### 業種別のカスタマイズ

データ分析の提案は、クライアントの業種によって重点ポイントが変わります。

**EC事業者の場合:**
- ファネル分析（商品閲覧→カート→購入）を強調（オプション導入を前提に）
- コホート分析（リピート率）の重要性を訴求（同上）
- チャネル別ROASの可視化を前面に出す

**SaaS事業者の場合:**
- ユーザーのアクティベーション率に焦点
- 解約率（チャーン）の分析を提案に含める
- MRR（月次定期収益）の可視化を提案

**メディア運営者の場合:**
- 表示回数・ユーザー数（GA4の指標）の詳細分析
- 記事別のエンゲージメント分析
- 広告収益の最適化に焦点

Claude Codeに業種を伝えると、テンプレートの「期待される効果」セクションを業種に合わせて書き換えてくれることが多いです。

### 提案書の品質チェック

カスタマイズした提案書をClaude Codeにレビューしてもらうことも有効です。

```text
以下の提案書をレビューしてください。
チェックポイント:
- クライアントの課題と提案内容の整合性
- 専門用語が多すぎないか
- 費用対効果の訴求が十分か
- 誇大表現がないか
- 「期待される効果」と「納品物」「拡張オプション」の間に食い違いがないか
```

提案書は技術的な正確さだけでなく、クライアントへの伝わりやすさも重要です。「非エンジニアの経営者にも伝わるか」という観点でレビューしてもらうと、改善点が見つかることが多いです。

## テンプレートの運用と改善

テンプレートは一度作ったら終わりではありません。案件を重ねるごとに改善していきます。

**改善サイクル:**

1. テンプレートを使って提案書を作成する
2. クライアントの反応をメモする（どの部分に興味を持ったか、どこで質問が出たか）
3. 反応が良かった表現はテンプレートに反映する
4. 質問が多かった部分は説明を追加する

このサイクルを回すことで、テンプレートの精度が上がり、受注率の向上が期待できます。

## 提案書以外への応用

このテンプレートの考え方は、提案書以外にも応用できます。

**月次レポートのテンプレート:**
クライアントへの月次レポートも、テンプレートを用意しておくと効率的です。数値の部分だけ毎月更新し、分析コメントをClaude Codeで生成するという運用が可能です。

**サービス説明資料:**
ココナラやポートフォリオサイトに掲載するサービス説明も、提案書のテンプレートをベースに作成できます。

**ヒアリングシート:**
提案書の「背景と課題」セクションは、クライアントへのヒアリング項目としてそのまま使えます。

## まとめ

- 提案書は構成がパターン化できるので、Markdownのテンプレートにして再利用すると作成の負担を減らしやすい
- 「自動化」は部品に分けて書く（スケジュールクエリ、データの鮮度）。効果の節と納品物・オプションは必ず揃える
- 次にやること: テンプレートを自分のサービスに合わせて直し、Claude Codeに整合性のレビューをさせる
