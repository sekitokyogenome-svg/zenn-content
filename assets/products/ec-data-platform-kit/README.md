# EC データ基盤 実装キット

GA4 × BigQuery で EC のデータ基盤を作るための、**動くもの一式**です。

記事や本は「やり方」を教えてくれますが、実際に手を動かすと、
散らばった断片を探して、繋いで、動くかどうか試す時間がかかります。
このキットはその時間を肩代わりするために作りました。

## 同梱物

| ディレクトリ | 中身 |
|---|---|
| `sql/` | 検証済み SQL **466本**＋用途別索引（`INDEX.md`） |
| `scripts/` | Python 自動化スクリプト **33本**＋`requirements.txt` |
| `dbt/` | dbt プロジェクト雛形（そのまま `dbt run` できる構成） |
| `looker-studio/` | ダッシュボードが参照する BigQuery ビュー **47個**＋フィールド定義書＋接続手順 |
| `prompts/` | Claude Code / Claude API で使うプロンプト **12本** |

## 前提環境

| 項目 | 前提 |
|---|---|
| GA4 | BigQuery エクスポートが有効（日次またはストリーミング） |
| データセット | `analytics_XXXXXXXXX` が存在（推奨ロケーション `asia-northeast1`） |
| 権限 | BigQuery のジョブ実行権限。ビュー作成にはデータセットの編集権限 |
| Python | 3.10 以上（`scripts/` を使う場合） |
| dbt | `dbt-bigquery`（`dbt/` を使う場合） |

## セットアップの順番

**1. SQL を試す（最短ルート・ここだけでも価値があります）**

`sql/INDEX.md` から目的に近いものを選び、2箇所を置き換えて実行します。

| プレースホルダ | 置き換える値 | 例 |
|---|---|---|
| `${PROJECT}` | GCP プロジェクト ID | `my-shop-analytics` |
| `${DATASET}` | GA4 のデータセット | `analytics_123456789` |

各ファイルの先頭に「用途 / 必要テーブル / コストの注意」を書いてあります。

**2. ダッシュボードのデータ層を作る**

`looker-studio/views/` のビューを BigQuery で作成してから、Looker Studio を接続します。
手順は `looker-studio/setup-guide.md` に書きました。

**3. パイプラインをコード管理する**

`dbt/` を使って staging → mart の変換を再現可能にします。`dbt/README.md` を参照。

**4. 定型作業を自動化する**

`scripts/` の Python を使います。依存は `pip install -r scripts/requirements.txt`。
どのスクリプトも認証情報の設定が必要です（`scripts/README.md` に一覧）。

## 実行前に必ずドライランを

BigQuery は読み取ったデータ量で課金されます。**ドライランは課金されません。**

```bash
bq query --dry_run --use_legacy_sql=false '<SQLをここに貼る>'
```

特に `events_*` を `_TABLE_SUFFIX` なしで叩くと全期間をスキャンして高額になります。
収録した SQL は原則として期間を絞ってありますが、期間の値は自社のデータに合わせて変更してください。

## 検証の範囲について（正直に書きます）

収録した SQL は **BigQuery の方言でパース検証を通したもの**です。
構文が壊れていないことを機械的に確認しています。

ただし、**検証できるのは構文までです。**

- 実際のスキーマはプロパティごとに違います（カスタムディメンションの有無、
  `collected_traffic_source` が入っているか、`items` を使っているか）
- Python スクリプトは構文チェック（`py_compile`）までで、実行検証はしていません。
  BigQuery や各種 API の認証が必要なためです

**自社のデータで動かして、数字が想定と合うかは必ず確認してください。**
そのための確認手順も SQL 側に用意しています（`sql/INDEX.md` の「データ基盤設計・運用Tips」）。

## Looker Studio について

`looker-studio/` に入っているのは**データ層**（ビュー定義・フィールド定義書・接続手順）で、
レポート本体は含まれていません。

Looker Studio のレポートはクラウド上の成果物で、ファイルとして配布する手段がないためです。
ビューを作ったあと、Looker Studio 上でレポートを1回組み立てる作業が必要になります。
その手順を `looker-studio/setup-guide.md` に書きました。

そのうえで、SQL は検証にかけ、構成と説明は確認したうえで公開しています。
